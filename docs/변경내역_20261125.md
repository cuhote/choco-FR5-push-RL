# fr5_push 변경 내역과 이유 (2026-11-24 ~ 11-25)

밀기 강화학습 환경(`fr5_push`)을 실물 기준과 새 트레이에 맞추고, 학습이 안 되던 문제를 고친 기록.
현재 설정 전체는 [`환경값_정리_20261125.md`](환경값_정리_20261125.md) 참고.

## 1. 큐브 수 18 → 19개

- 파일: `fr5_push_env_cfg.py` `NUM_CUBES`
- 이유: 실물은 글자 16개(R, E, E, D, O, A, N, G, Y, L, L, W, B, U, P, P) + 숫자 3개 = 19개.

## 2. 잡기 판정·동작을 실물(`choco_ws/src/fr5_task/config/points.yaml`)에 맞춤

| 항목 | 이전 | 지금 | 실물 |
|---|---|---|---|
| 필요한 틈 깊이 | 이웃 쪽 15mm / 벽 쪽 18.5mm | **18mm** (벽 쪽도 같음) | `GAP_MIN: 18.0` |
| 필요한 틈 폭 | 16mm | **20mm** | `FINGER_WIDTH: 20.0` |
| 집기 전 벌림 | 손가락마다 19.5mm (89%, 합 39mm) | **15.4mm (70%, 합 30.8mm)** | `GRIP_OPEN_PCT: 70` |
| 잡을 때 손끝 높이 | 12.5mm | **12mm** | `Z_TIP_ABOVE_FLOOR: 12.0` |

- 이유: 실물은 "틈이 18mm 이상이면 집는다"로 판단한다. 시뮬이 다른 기준(15mm)으로 "열렸다"고 보고 멈춘 상태를 실물은 "막혔다"고 볼 수 있어서, 학습한 정책이 실물에서 다르게 동작한다.
- 18mm 근거: 손가락 안쪽 면이 큐브 면에서 2.9mm(15.4 − 12.5) + 손가락 두께 최대 약 11mm + 여유 약 4mm.
- 성공 판정은 "실제로 집어서 30mm 넘게 들림" 그대로 둔다. 18mm는 "집기를 시도할지" 정하는 기준이고, 성공 판정은 결과 채점이라 역할이 다르다.

## 3. 인식 오차

- 파일: `fr5_push_env_cfg.py` `obs_noise_dist`, `obs_pos_noise_std`, `obs_yaw_noise_deg` / `fr5_push_env.py` `cubes_observed()`
- 이전: 정규분포 σ2mm, σ2° → 지금: **균등분포 ±3mm, ±5°** (x, y, yaw 각각)
- 이유: 설계서 인식 오차 범위. 노이즈는 계획(관측·후보·판정)에만 적용하고 물리와 성공 판정은 참값.
- 균등분포도 쓸 수 있게 `cubes_observed()`에 옵션을 추가함.

## 4. 미는 거리: 큐브 기준 15 / 25 / 35mm

- 파일: `fr5_push_env_cfg.py` `CAND_DISTS` / `fr5_push_env.py` `build_candidates()`
- 이전: `CAND_DISTS = (0.040, 0.030)`가 **손가락 이동 거리**였고, 그 안에 큐브까지 다가가는 구간(8mm)이 포함돼 있어서 큐브는 실제로 32 / 22mm만 밀렸음.
- 지금: `CAND_DISTS = (0.035, 0.025, 0.015)`가 **큐브가 밀리는 거리**. 손가락 이동 = 이 값 + 내려가는 위치(5mm).
- 거리가 3종이 되어 후보가 148 → **220개**, 관측 크기가 1,827 → **2,691**로 늘어남.
- 35mm + 5mm = 40mm = 밀기 시간 1.6초 × 25mm/s 라서 시간표는 그대로 맞음.

## 5. 내려가는 위치 5mm, 안전 여유 2mm

- 파일: `fr5_push_env_cfg.py` `start_clearance` 0.008 → 0.005, `safety_margin` 0.004 → 0.002
- 이유: 착지 자리로 비어 있어야 하는 길이가 "띄우는 거리 + 손가락 폭 14mm + 여유"라서, 8mm·4mm면 큐브 19개가 빽빽한 트레이에서 시작점을 못 찾을 수 있음.
- 결과: 측정에서 시작점 막힘 0%, 큐브 위 착지 0%. 여유(2mm)가 인식 오차(±3mm)보다 작지만 착지 문제는 생기지 않았음.

## 6. 시작점 막힘 = 실패 −5

- 파일: `fr5_push_env_cfg.py` `fail_on_blocked = True` / `fr5_push_env.py` `_get_dones()`
- 이전: 안전한 후보가 하나도 없으면 내려가지 않고 밀기 1회만 소모, 벌점 없음.
- 지금: 실패(−5)로 그 판을 끝냄. `push_demo.py`와 학습 로그에 비율(`blocked_rate`)을 따로 출력함.

## 7. 틈 보상: 모자란 틈 1mm 줄 때마다 +0.17

- 파일: `fr5_push_env_cfg.py` `rew_gap_per_mm = 0.17` / `fr5_push_env.py` `_pre_physics_step()`, `_get_dones()`, `_get_rewards()`
- 계산: 밀기 전과 후의 "대상이 열리기까지 모자란 깊이"(두 축 중 나은 쪽, 참값)를 비교해 줄어든 mm × 0.17. 늘어나면 같은 크기로 감점. 실패한 판에는 주지 않음.
- 크기: 모자란 깊이 최대 36mm(18mm × 양쪽) → 최대 약 +6점 (성공 +10보다 작게).
- 밀기 후 깊이는 잡기 동작 전에 계산 (잡으면 대상이 들려서 값이 달라지므로).

## 8. 밀 때 손가락을 닫힘 위치에 고정

- 파일: `fr5_push_env_cfg.py` `lock_fingers_push = True` / `fr5_push_env.py` `_apply_action()`
- 이전: 손가락을 "닫힘 목표 + 강성 2000, 최대 100N"으로 당기기만 해서, 큐브에 밀리면 벌어졌음. 쌓임 재생 로그에서 밀기 끝 무렵 **최대 2.9mm** 벌어진 것을 확인.
- 지금: 밀기 동안 매 물리 스텝마다 손가락 위치를 0으로 고정.
- 이유: 실물 그리퍼는 닫힌 채 위치를 유지함. 벌어진 손가락 사이에 큐브가 끼거나 들 때 딸려 올라가는 것을 방지.

## 9. 규칙 점수 + 정책 보정 (가장 큰 변경)

- 파일: `fr5_push_env_cfg.py` `residual_rule = True`, `rule_weight = 1.0` / `fr5_push_env.py` `_pre_physics_step()`

### 문제

1~8번을 반영하고 학습을 시작했는데(`2026-11-25_01-09-47_tray30_c19_cand220`), 51 iteration(약 2시간) 동안 학습이 전혀 되지 않았다.

| 지표 | 지난 학습 (후보 56개) | 이번 (후보 220개) |
|---|---|---|
| 성공률 | 59% → 75% (150 iteration) | **49~53%에서 그대로** (무작위 52.2%와 같은 수준) |
| 열린다고 예측된 후보를 고른 비율 | 38% → 69% | **39~40%에서 그대로** |
| 탐색 노이즈 | 줄어듦 | 0.50에서 안 변함 |

### 원인

기존 방식은 정책이 후보 220개 각각에 점수를 내고, 학습 중에는 그 점수 모두에 탐색 노이즈(표준편차 0.5)를 더한 뒤 최고점 하나를 실행한다.

1. **노이즈가 선택을 결정한다.** 처음 정책 점수 차이는 아주 작아서 220개 중 최고점은 거의 항상 "노이즈가 가장 크게 뽑힌 후보"가 된다. 사실상 무작위 선택.
2. **학습 신호가 220개에 흩어진다.** 결과에 영향을 준 건 선택된 후보 1개의 점수인데, 이 방식(PPO 연속값 정책)은 220개 점수 전체를 같이 고친다. 결과와 무관한 219개의 노이즈에 신호가 묻힌다. 후보 56개일 때도 강화학습이 규칙을 넘지 못했는데(진행 기록), 후보가 220개로 늘면서 더 심해졌다.

### 해결

```
이전: 실행할 후보 = argmax(정책 점수 + 노이즈)
지금: 실행할 후보 = argmax(탐색 규칙 점수 + 정책 점수 + 노이즈)
```

- 처음부터 **규칙 수준으로 행동**한다. 정책이 아무것도 몰라도 규칙이 고른 후보가 실행됨.
- 노이즈는 **규칙 점수가 비슷한 후보끼리만** 선택을 바꾼다. 엉뚱한 후보는 거의 고르지 않고 의미 있는 대안끼리만 비교해 봄.
- 정책은 **규칙이 틀리는 경우만** 보정하도록 배우면 된다.
- 정책이 보정을 못 배워도 규칙보다 크게 나빠지지 않는다. 실물에서도 규칙 코드는 어차피 있어야 함.

### 결과 (학습 시작 직후)

| 지표 | 이전 방식 | 지금 (0~1 iteration) |
|---|---|---|
| 성공률 | 50% | **87.2%, 85.0%** |
| 열린다고 예측된 후보를 고른 비율 | 40% | 84~85% |
| 평균 보상 | 약 2.5 | 7.7~8.3 |

87.5%(탐색 규칙)를 넘어설지는 학습을 더 봐야 안다. 약 50 iteration까지 오르지 않으면 정책이 규칙보다 나은 걸 못 배우는 것이므로, 실물에는 규칙을 쓴다.

## 10. 규칙 점수 크기 조정, 탐색 노이즈 0.3

- 파일: `fr5_push_env.py` `demo_push_action()` / `agents/rsl_rl_ppo_cfg.py` `init_noise_std`

탐색 규칙은 바로 열리는 후보가 없을 때 "다음 수에 열리는가"와 "모자란 깊이"로 점수를 매긴다. 깊이 단위가 m라서 10mm 차이가 0.1점밖에 안 됐고, 9번에서 노이즈(0.3~0.5)에 묻혔다.

| 항목 | 이전 | 지금 |
|---|---|---|
| 다음 수에 열림 | +1 | **+4** |
| 모자란 깊이 | 1mm당 −0.01 | **1mm당 −0.1** |
| 바로 열림 예측 / 줄줄이 밀림 없음 | +2 / +0.5 | 그대로 |
| 탐색 노이즈 (정책) | 0.5 | **0.3** |

- 다음 수 열림(4점)이 모자란 깊이 최대치(36mm × 0.1 = 3.6점)보다 커서, **규칙의 우선순위**(다음 수 열림 → 모자란 깊이)는 이전과 같다.
- 노이즈 0.3이면 점수 차이 0.5점인 후보끼리는 약 12%, 1점이면 약 1%, 2점 이상이면 거의 0%만 선택이 바뀐다.
