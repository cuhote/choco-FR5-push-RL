## T5. rsl_rl 학습 — 후보 220개, 연속값 점수 (11/25 01:09)

- **방식**: 정책이 후보 220개 각각에 점수 + 탐색 노이즈(σ0.5) → 최고점 실행 (기존 방식)
- **명령**: `python -u scripts/rsl_rl/train.py --task Template-Fr5-Push-Direct-v0 --headless --num_envs 512 --seed 0 --max_iterations 300 --run_name tray30_c19_cand220`
- **결과**:

| iteration | 0~19 | 20~39 | 40~59 | 100~119 | 200~219 |
|---|---|---|---|---|---|
| 성공률 (학습 중 평균) | 51.0% | 51.6% | 52.8% | 58.3% | 68.5% |

  - 51 iteration 시점: 성공률 49~53% (무작위 52.2% 수준), 탐색 노이즈 0.50 고정, 열림 예측 후보 선택 39~40% 고정
- **해석 (원인 확인됨)**: 처음 정책 점수 차이가 노이즈보다 작아 사실상 무작위 선택. 결과에 영향을 준 건 선택된 후보 1개인데 220개 점수 전체를 같이 고쳐 학습 신호가 흩어짐
- **정정**: 51 iteration에서 "학습이 안 된다"고 판단했지만, 실수로 프로세스가 계속 돌아 222 iteration까지 가 보니 **아주 느리게(20 iteration마다 약 2%p) 오르고 있었음**. 그래도 70%로 규칙(87.5%)보다 한참 낮음
- **관련 문제**: 셸 PID만 종료돼서 이 학습이 T6과 동시에 돌았음 (둘 다 iteration당 약 172초로 느려짐)

- **학습 중**: 0 iteration부터 85~87%, 168 iteration까지 84~86%에서 평평. 노이즈 0.30 고정
- **평가** (`evaluate.py`, 환경 256개, 탐색 없음):

|---|---|---|---|---|---|---|

- **해석**: 규칙 수준으로 출발하는 건 성공(무너지지 않음), 하지만 규칙을 넘는 보정은 못 배움. 학습 방식의 한계(T5와 같은 원인)가 그대로 남음

## T7. 분석 1 — 기하 상한 (11/25 10:50)

- **목적**: 후보 220개로 3번 안에 열 수 있는 조합이 있는지 (물리 없이 기하 예측, 2·3번째는 진전 상위 8개만)

- **해석**: 기하 상한(84.8%)이 규칙의 실제 성공률(87.5%)보다 낮음 → 기하 예측이 보수적. "여유가 없다"는 증거로 보였으나, T8에서 뒤집힘

## T8. 분석 2 — 물리 상한, 밀기 1번 (11/25 11:00)

- **목적**: 같은 배치에서 후보 220개를 하나씩 **실제 물리로** 밀어 보고, 규칙이 놓친 더 나은 후보가 있었는지 확인
- **스크립트**: `scripts/tools/oracle_check.py` (새로 작성). 배치 저장 → 후보마다 되돌리고 밀기 1번 → 참값 18mm 열림 + 실패 없음
- **명령**: `python -u scripts/tools/oracle_check.py --num_envs 256 > logs/analysis_2_oracle.log` (약 6분)

| | 열린 비율 |
|---|---|
| 탐색 규칙이 고른 후보 | 74.6% |
| 220개 중 하나라도 열림 | **88.3%** |

## T9. categorical PPO 학습 (11/25 11:23)

- **바꾼 것** (`scripts/cat_ppo/train_cat.py`, 새로 작성):
  1. categorical 정책: 후보 i를 고를 확률 = softmax(점수), 안전하지 않은 후보는 확률 0
  2. 후보마다 같은 신경망: 점수_i = f(대상 주변 51 + 후보 i 특징 12), 220개에 공통 (128-128, 파라미터 105,602개)
  3. PPO: 학습률 3e-4, 엔트로피 0.01, gamma 0.9, lambda 0.95, clip 0.2, epochs 5, mini-batch 4. 규칙+보정은 끔
- **명령**: `python -u scripts/cat_ppo/train_cat.py --num_envs 512 --iters 300 --run_name cat_v1 > logs/train_cat_v1.log`
- **결과** (학습 중, 확률대로 뽑음):

| iteration | 0 | 14~18 | 36~39 | 50~63 |
|---|---|---|---|---|
| 성공률 | 55.2% | 84~87% | 85~87% | 86~89% |
| 엔트로피 (e^값 = 사실상 고르는 후보 수) | 4.50 (약 90개) | 2.5~2.8 (약 12~16개) | 1.8~1.9 (약 6개) | 1.5~1.6 (약 5개) |

- **T5와 비교**: 같은 18~20 iteration 시점에 rsl_rl 51% vs categorical 85.5%
- **중단·재개**: 50 iteration에서 멈춤(`kill`로 안 꺼져 `kill -9`), `model_49.pt`에서 `--resume`으로 재개 (14:06, `logs/cat_ppo/2026-11-25_14-06-41_cat_v1_resume/`)

## T11. `model_39` vs 탐색 규칙 — 같은 배치 (11/25 13:00)

- **바꾼 것**: 평가 모드에 `--eval_policy look/demo` 추가 → 같은 시드(1000)로 규칙과 모델을 같은 배치에서 비교. 환경 384개 × 밀기 24번
- **명령**:
  - `python -u scripts/cat_ppo/train_cat.py --eval_policy look --num_envs 384 --pushes 24 > logs/eval_same_look.log`
  - `python -u scripts/cat_ppo/train_cat.py --eval .../model_39.pt --num_envs 384 --pushes 24 > logs/eval_same_cat39.log`
- **결과**:

| | 판 수 | 1번 | 2번 | 3번 | 실패 |
|---|---|---|---|---|---|
| 탐색 규칙 | 5,862 | 64.0% | 81.4% | 85.9% | 0.3% |
| **categorical `model_39`** | 6,195 | **69.5%** | **84.3%** | **88.2%** | 0.2% |

- **해석**: 차이 오차 약 ±1.2%p(95%)보다 큼 → **강화학습이 규칙을 넘음**. 첫 밀기 차이가 가장 커서 T8의 결과와 맞음. 같은 판 수에서 판이 더 많이 끝남 = 더 적은 밀기로 성공
- **교훈**: 탐색 규칙이 배치에 따라 85.9~87.8%로 2%p 흔들림. 1~2%p 차이를 비교할 때는 **같은 배치 + 큰 표본**이 필수 (T10에서는 차이가 안 보였음)

  - A: 3번 밀어도 "열림" 판정이 한 번도 안 남 → 행동(후보) 한계
  - B: "열림"으로 잡기를 시도했지만 못 듦 → 잡기 조건 문제 (그중 참값으로는 안 열려 있던 경우 = 인식 오차)
  - F: 실패로 끝남
  - 시작 배치의 벽 상황별(벽 무관 / 한 축이 벽에 막힘 / 두 축 다 막힘)로 나눔

  1. 남은 실패는 거의 다 **A(3번 밀어도 열림 판정이 안 남)**. 잡기 실패(B)는 0.6%로 작음. 앞서 "잡기 시도의 약 7%가 실패"라고 본 건 시도 횟수 기준이었고, 대부분 다음 밀기 뒤 다시 잡아 성공하므로 **판 기준으로는 0.6%**
  2. 실패가 **벽에 붙은 대상에 몰려 있음**. 전체 실패 10.9%p 중 한 축 막힘이 약 6.0%p, 두 축 막힘이 약 3.9%p, 벽 무관은 약 0.9%p → **약 91%가 벽 때문**
  3. 벽 무관 배치는 규칙도 이미 98%라 개선 여지가 거의 없음. 강화학습이 규칙을 넘은 곳은 **벽 상황**이고, 특히 두 축 다 막힌 경우 22.6% → 47.1%로 두 배
  4. 성공률이 87~89%에서 평평한 이유: 남은 실패가 대부분 "지금 후보로는 벽에서 떼어 낼 수 없는" 배치이기 때문 (T7의 기하 분석과 같은 결론)
- **다음**: 벽에 붙은 대상을 다루는 행동을 후보에 추가 (벽 따라 더 다양하게 밀기, 비스듬히 밀어 돌리기 등). 또는 벽 쪽 틈 기준(18mm)이 실제보다 엄격한지 실물에서 확인
