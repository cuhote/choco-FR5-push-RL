# 인수인계: FR5 팔을 붙여서 학습하기 (2026-11-26)

지금 학습은 **팔 없이 떠 있는 PGEA 그리퍼**로 했다. 이 문서는 FR5 + PGEA + D435 모델(`assets/usd/fr5_pgea_v2/`)로
옮겨서 확인·학습할 때 할 일을 정리한다. 줄 번호는 이 커밋 기준.

## 0. 먼저 알아 둘 것: 처음부터 다시 학습할 필요는 없다

정책이 고르는 것은 "어느 큐브를 / 어느 방향으로 / 몇 mm / 트레이의 어느 지점에서 시작해 밀지"(트레이 좌표)이고,
팔은 손끝(TCP)을 그 경로로 움직이기만 한다. FR5는 위치 제어가 정확해서 손끝이 같은 경로로 움직이면 큐브도 같게 밀린다.
그래서 순서는 **확인 → (필요하면) 후보 제한 → 지금 모델에서 이어서 학습**이다.

| 단계 | 내용 | 물리 시뮬 필요 |
|---|---|---|
| 1. 도달 가능 확인 | 트레이 전체에서 손끝 수직 자세 + 그리퍼 각도(미는 방향 + 90°, [−90°, 90°))가 FR5 관절 범위 안인지 IK로 계산 | 없음 (기구학만) |
| 2. 팔로 실행해 평가 | FR5 + IK로 지금 모델(`--eval`)을 몇백 판 돌려 성공률이 떠 있는 그리퍼와 비슷한지, 팔 링크가 벽·큐브에 닿는지 | 있음 |
| 3. 이어서 학습 | 1·2에서 문제가 된 후보만 안전 검사에서 빼고 `--resume`으로 짧게 학습 | 있음 |

## 1. 필요한 실측값

| 값 | 어디에 쓰나 | 상태 |
|---|---|---|
| **FR5 베이스 위치** (트레이 중심 기준 x, y, 높이, 회전) | 로봇 배치, IK, 도달 가능 계산 | **미측정** |
| 트레이 바닥 높이 (로봇 좌표) | 손끝 17mm(밀기), 12mm(잡기) 높이 기준 | 티칭으로 측정 필요 |
| TCP | 플랜지 → 손가락 끝 160mm | `points.yaml` `TCP: [0,0,160]`과 같음 |
| 하우징 크기 | 벽 충돌 검사 | 시뮬 73 × 23mm vs D435 URDF 55 × 40mm 불일치. 실물 확인 필요 |

## 2. 코드에서 바꿀 곳 (`source/fr5_push/fr5_push/tasks/direct/fr5_push/`)

지금 그리퍼는 가상 관절 `px, py, pz, yaw`(+ `finger_left/right_joint`)로 손끝 위치를 **관절값으로 바로** 준다.
FR5는 `j1`~`j6`이라 **손끝 목표 → 관절값을 IK로** 바꿔야 한다.

| 위치 | 지금 | FR5에서 |
|---|---|---|
| `fr5_push_env_cfg.py` `GRIPPER_CFG`, `robot_cfg` (`:68`, `:166`) | `GRIPPER_USD`, 가상 관절 액추에이터 `gantry`, `yaw` | `FR5_PGEA_USD`(이미 경로 정의됨), `j1`~`j6` 액추에이터와 게인, 베이스 위치(`init_state.pos/rot`) |
| `fr5_push_env.py:22` `self._j` | `px, py, pz, yaw` 관절 인덱스 | `j1`~`j6` 인덱스 + `tcp` 바디 인덱스 |
| `fr5_push_env.py:325` `_joint_targets(xy, tip_z)` | 관절 = (x, y, z + 0.16, yaw) | **IK**: 목표 TCP 위치 (x, y, tip_z), 자세(아래를 봄 + yaw) → `j1`~`j6`. Isaac Lab `DifferentialIKController` 사용 권장 |
| `fr5_push_env.py:106`, `:397`, `:612` `write_joint_state_to_sim` | 밀기·잡기 시작 때 그리퍼를 시작점으로 **순간 이동** | 팔도 IK 해로 순간 이동하거나, 실제처럼 이동 시간을 넣음 (안전 높이에서 이동) |
| `fr5_push_env.py:154` 착지 판정 | `pz 관절값 − 0.16` = 손끝 높이 | `tcp` 바디의 z 위치로 |
| `fr5_push_env.py:410` 디버그 출력 | 같은 방식 | 같은 방식으로 수정 |
| `fr5_push_env.py:150` 손가락 고정 | `finger_.*` 관절 | 관절 이름이 같으면 그대로 |

**바꾸지 않아도 되는 것**: 후보 생성(`build_candidates`), 안전 검사(`landing_free`), 열림 판정(`grasp_axes_clear`),
보상, 관측, `scripts/cat_ppo/train_cat.py` 전체. 모두 트레이 좌표와 큐브 위치만 쓴다.

## 3. 주의할 점

- **속도**: 팔(관절 6개) + IK가 붙으면 iteration당 시간이 늘어난다. 지금 떠 있는 그리퍼로 환경 512개 기준 약 2분
- **IK 해 선택**: 같은 손끝 위치에 관절 해가 여러 개일 수 있음. 손목이 뒤집히지 않게 시작 자세를 정하고 이전 해에서 이어서 풀기
- **손목 회전**: 밀기마다 그리퍼 각도가 바뀜(미는 방향 + 90°). `j6` 범위 안인지 1단계에서 확인
- **충돌**: 밀기 높이(손끝 17mm)에서 손목·팔 링크가 트레이 벽(30mm)이나 큐브에 닿는지 2단계에서 확인. 닿는 후보는 안전 검사에서 뺌
- **실물 실행은 시뮬과 다름**: 실물 FR5는 Fairino 컨트롤러(`MoveL`)가 움직인다. 시뮬의 관절 제어를 학습하는 게 아니라 **정책(후보 선택)만** 실물로 가져간다

## 4. 지금 모델로 시작하기

1. GitHub Release에서 최신 모델(`model_*.pt`) 받기
2. 떠 있는 그리퍼로 같은 숫자가 나오는지 먼저 확인 (환경이 제대로 설치됐는지 확인용):
   ```bash
   python -u scripts/cat_ppo/train_cat.py --eval <model.pt> --num_envs 384 --pushes 24 2>&1 | grep -v "^\[eval\]"
   ```
   `model_139` 기준 약 91% (같은 시드라도 GPU에 따라 ±1%p 정도 차이 날 수 있음)
3. 2절을 바꾼 뒤 같은 명령으로 FR5 평가 → 4. 필요하면 `--resume <model.pt>`로 이어서 학습

## 5. 남은 결정

- **벽 대응**: 남은 실패의 약 91%가 벽에 붙은 대상. 방향 후보
  - 밀다가 큐브를 벽에 붙이면 벌점(보상 변경) → 벽 쪽으로 미는 것을 피함
  - 큐브를 처음부터 벽에서 떨어뜨려 배치 → 벽 무관 배치 성공률 98.8%에 가까워짐. 단 실물 상자에서도 보장돼야 함
  - 벽 대응 밀기 후보 추가 (벽 따라 다양하게, 비스듬히 밀어 회전)
- **최대 밀기 횟수**: 시뮬은 3번(설계서·상태머신은 2번). 3번이 약 4.6%p 높음
