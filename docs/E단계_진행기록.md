# E단계 진행 기록 (2026-11-22)

시뮬레이션: 떠 있는 PGEA 그리퍼, 트레이 + 25mm 큐브 18개, 대상(빨강)은 두 잡기 축이 모두 막힌 큐브.

## 결정한 것

| 항목 | 결정 | 이유 (측정) |
|---|---|---|
| 동작 | **밀기만** 사용, 밀고 → 카메라로 다시 보고 → 다시 계획 | 요구사항 |
| 최대 밀기 | **3번** (넘으면 사람 호출) | 규칙 기준 2번 58.8% / 3번 64.7%, 4번 이상은 거의 안 늘고 넘어짐만 늘어남 |
| 행동 형식 | **안전한 후보 56개 중 선택** (이웃 6 x 옆면 2 x 방향 2 x 거리 2 + 대상 4면 x 거리 2) | 연속 행동은 큐브 위 착지 29~43%. 후보 방식은 착지 0% |
| 안전 검사 | 착지 자리(손가락 21x21mm) + 하우징 + 카메라가 큐브·벽에 닿지 않음, 여유 4mm | 그리퍼 파손 방지. 실물 소프트웨어에도 같은 검사 |
| 시작 간격 | 밀 큐브 옆면에서 8mm 떨어져 내림 | 여유 4mm 보다 커야 함 (3mm 일 때 필터가 99% 막음) |
| 잡기 벌림 | **손가락마다 19.5mm (약 89%, 합 39mm)** | 70% 는 카메라 오차(σ2mm)에서 열림 판정의 77% 만 잡힘 -> 89% 에서 97.6% |
| 잡기 판정 깊이 | 큐브 면 바깥 **20.5mm** x 폭 22mm 비어야 열림 | 위 벌림 + 손가락 두께 13mm + 여유 |
| 손가락 (시뮬) | 밀 때 2000/100N, 잡을 때 200/5N | 100N 으로 잡으면 시뮬에서 손가락이 15g 큐브를 뚫음 (잡힘 0%) |
| 밀기 후 | 5mm 물러난 뒤 들기 | 들 때 큐브를 끌어올리는 경우 감소 (381 -> 280건) |
| 트레이 (1차) | 벽 80 -> 40mm, 네 모서리 삼각형 블록(변 50mm) | 벽 80mm 에서는 못 푸는 경우의 63% 가 벽 때문 (하우징이 벽에 걸림). 상한 70% -> 84% |
| **트레이 (현재)** | **손잡이 쟁반: 안쪽 400 x 275mm(가정), 테두리 20mm, 직각 모서리** | 규칙 77.9% / 탐색 78.7%, 상한 86.1% (아래 표) |
| 카메라 | D435 아래를 수직으로 봄, 촬영은 높은 자세에서. 치수는 **추정값** (아래 면 = 손가락 끝 + 55mm) | 테두리 20mm 라 벽에 안 걸림 |
| 카메라 노이즈 (시뮬) | 위치 σ2mm, 각도 σ2° (계획에만 적용) | 실제 D435 오차 측정 후 교체 |

| "열림 예측" 밀기의 실제 정확도 | 67.7% | 67.1% |

상한으로도 못 푸는 경우: 테두리 때문에 두 축 불가 61%, 한 축 불가 32%, 테두리와 무관 7%.

## 남은 문제

1. **테두리·모서리에 붙은 큐브** (상한으로도 못 푸는 경우의 93%): 실제 쟁반 테두리 모양(기울기) 반영 후 재평가
2. **큐브 쌓임 3.6%** (이전 트레이 4~8%): 거의 전부 "들기" 단계. 원인 미확정 -> 화면으로 확인 필요
3. **예측 오차**: "열림 예측" 밀기의 실제 정확도 67.7% (노이즈 없을 때는 더 높음) -> 실제 D435 오차 측정, 여러 장 평균
4. **계획 상한 86.1%**: 후보 종류 추가 / RL
5. 실측 필요: **쟁반 바닥 평평한 부분 크기, 테두리 높이·기울기**, D435 장착 위치, 하우징 깊이(Y, 40mm 가정),
   손가락 폭(Y, 20mm 가정), 큐브 재질
6. 실제로 쏟은 배치 사진: 모서리·테두리에 큐브가 얼마나 자주 붙는지에 따라 실제 성공률이 크게 달라짐

## 스크립트 (fr5_push 폴더에서)

```bash
python scripts/push_demo.py --num_envs 4                                   # 화면으로 보기 (규칙)
python scripts/push_demo.py --num_envs 4 --policy look                     # 탐색 규칙
python scripts/rsl_rl/evaluate.py --task Template-Fr5-Push-Direct-v0 --num_envs 256 --headless --policy demo
python scripts/rsl_rl/train.py --task Template-Fr5-Push-Direct-v0 --headless --num_envs 512
python scripts/tools/grasp_check.py --noise       # 잡기 판정 검증
python scripts/tools/lookahead_check.py           # 1/2/3번 조합 상한 (기하)
python scripts/tools/stack_check.py               # 쌓임이 생기는 단계
```

학습은 환경 512개 권장 (1024개에서 GPU 오류로 재부팅이 필요했던 적 있음).
